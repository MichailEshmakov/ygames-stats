# Аналитика Яндекс Игр

Веб-инструмент для поиска и разбора каталога игр на площадке
[Яндекс Игры](https://yandex.ru/games): выкачивает каталог целиком в JSON и
даёт искать по нему офлайн — по ключевым словам, названию, тегам и
категориям, со сводкой и сортировкой по числу оценок и по приросту оценок
за 30 дней.

Бэкенда нет: данные лежат файлами в `public/data/`, страница читает их и
считает всё в браузере. Наружу ничего не уходит.

## Что нужно

- Node.js 20.19+ (или 22+);
- около 100 МБ на диске под каталог и кэш обхода.

## Локальный запуск

```bash
npm install
npm run collect        # полный обход каталога, ~20 минут
npm run collect-delta  # прирост за 30 дней с game-analytics.ru, ~40 минут
npm run dev            # откроется страница поиска
```

Каталог собирается один раз, дальше достаточно `npm run dev`. Чтобы
посмотреть на инструмент, не дожидаясь полного обхода, хватит пробного
прогона: `node scripts/collect.mjs --pages 20`.

Собрать данные можно и прямо со страницы: в шапке есть кнопка «Загрузить
данные» — она одним нажатием обходит каталог, а следом собирает прирост с
game-analytics.ru, запуская те же скрипты и показывая живой лог. Под кнопкой
написан объём: сколько весят файлы прошлого сбора, столько же нальётся и в
этот раз. Галочка
«Перечитать описания» добавляет к обходу тексты карточек: описание и «как
играть» меняются редко, поэтому по умолчанию берутся из прошлого каталога.

Работает это только под `npm run dev`: ни API Яндекса, ни
game-analytics.ru не отдают CORS-заголовков, поэтому сеть за браузер
обходит dev-сервер (плагин `collectorApi` в [vite.config.ts](vite.config.ts)).

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Дев-сервер Vite со страницей поиска |
| `npm run build` | Проверка типов и сборка статики в `dist/` |
| `npm run preview` | Просмотр собранной статики |
| `npm run collect` | Обход каталога: `public/data/catalog.json`, `tags.json`, `categories.json` и снимок `data/history/<дата>.json` |
| `npm run collect-delta` | Прирост оценок за 30 дней → `public/data/delta30.json` |

Ключи сборщиков — в шапках [scripts/collect.mjs](scripts/collect.mjs) и
[scripts/collect-delta.mjs](scripts/collect-delta.mjs): `--pages`,
`--resume`, `--delay`, `--lang`, `--refresh-details`, `--from`.

## Откуда берётся прирост за 30 дней

Площадка эту величину не отдаёт, поэтому источников два, и они друг друга
дополняют:

- **свой** — каждый прогон `npm run collect` кладёт число оценок в
  `data/history/<дата>.json`, прирост считается как разница с ближайшим
  снимком возрастом 20–45 дней. Точный, но появляется только через месяц
  регулярных прогонов;
- **чужой** — `npm run collect-delta` берёт готовые цифры с
  game-analytics.ru. Доступен сразу, покрывает около 85% игр, у которых
  вообще есть оценки.

Приложение грузит оба и ставит свой замер выше чужого; под таблицей
подписано, откуда взята цифра и на какую дату.

`data/history/` — единственные данные, которых нет в `.gitignore`: всё
остальное пересобирается командами выше, а прошлые снимки восстановить
задним числом неоткуда. Чистить эту папку нельзя.
